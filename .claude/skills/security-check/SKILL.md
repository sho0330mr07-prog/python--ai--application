# セキュリティチェック

このリポジトリは個人用のAIライティングツール（Python + Streamlit + `google-genai`）。DBも認証も**意図的に**持たず、状態は `st.session_state` にしかない。このため、一般的なWebアプリのチェックリスト（SQLインジェクション、セッション管理、CSRFトークンなど）をそのまま当てはめても、ノイズが多いだけになる。見るべきなのは「このアプリが実際に持っている資産」と「それが誰に届きうるか」だ。

- **守る資産**: Gemini APIキー（漏れると他人に課金される）、ユーザーが貼り付ける文章（受信メールなど個人情報を含みうる）、生成履歴
- **主な経路**: Streamlitサーバーへのネットワークアクセス、LLMへの入力（プロンプトインジェクション）、LLMの出力の描画、依存パッケージ、リポジトリに混入するファイル

指摘には必ず「どういう条件で、誰が、何をできるか」を書く。たとえば「認証がない」だけでは指摘にならない。認証がないのは設計上の判断だからだ。「LANに公開された状態で起動すると、同じネットワークの人がAPIキーを使える」なら指摘になる。

## 手順

### 1. 自動スキャンを実行する

```bash
python3 .claude/skills/security-check/scripts/scan.py .
```

標準ライブラリだけで動き、次の項目を機械的に調べる: 秘密情報らしき文字列、`.gitignore` の漏れ、秘密情報をウィジェットの初期値にしている箇所、`unsafe_allow_html` や `eval` などの危険なAPI、Streamlitの設定、バージョンを固定していない依存パッケージ、外部から入れたスキル。

スキャンの結果は**手がかり**であって結論ではない。誤検知（`.env.example` のプレースホルダーなど）は捨て、実際にコードを開いて確かめてから採用する。スクリプトはAPIキーの値そのものを表示しない（先頭数文字だけ）。レポートにもキーの全体を書き写さないこと。

### 2. 依存パッケージの既知の脆弱性（任意）

`pip-audit` が使えればそれを実行する。入っていなければ、インストールしてよいかユーザーに確認する（`pip install pip-audit` はネットワークにアクセスし、環境を変更するため）。断られたり、オフラインだったりする場合は、`.venv` に入っている実際のバージョン（`pip list`）をレポートに書き、「未確認」として扱う。ここで止まらずに次へ進む。

### 3. コードを読んでレビューする

`references/checklist.md` を読み、各項目をこのコードベースに当てはめて確認する。特に `app.py`（サイドバーの設定欄、結果表示、エラー表示）、`writing_tools/tools.py`（ユーザー入力からプロンプトを組み立てる部分、ファイルアップロード）、`writing_tools/gemini_client.py` は全文を読む。新しいツールやファイルが追加されていれば、それも対象に入れる。

### 4. 必要なら動かして確かめる

指摘が「実際にそうなるか」で重大度が変わる場合（例: APIキーがブラウザに送られているか）は、`streamlit.testing.v1.AppTest` で確認してよい。`app.py` は絶対パスで渡し、`GeminiClient.stream` をモンキーパッチして実際のAPIは呼ばない。APIキーには偽の値を使う。

### 5. レポートを書く

日本語で、次の形式にする。コードは修正しない。修正案は示すが、適用するかどうかはユーザーが決める。ユーザーに頼まれた場合だけ修正する。

```markdown
# セキュリティチェック結果

## 概要
（2〜4行。全体の評価と、一番先に対処すべきこと）

## 前提とした利用環境
（例: 自分のPCでのみ起動 / LANに公開 / インターネットに公開。わからなければ想定を明記し、環境ごとに重大度が変わる指摘はその旨を書く）

## 指摘事項

### [重大度] タイトル
- **場所**: `path/to/file.py:行番号`
- **内容**: 何が問題か
- **悪用シナリオ**: どういう条件で、誰が、何をできるか
- **修正案**: 具体的なコード、または設定の変更

（重大度の高い順に並べる）

## 問題なしと確認した項目
（確認して問題がなかった観点を短く列挙する。何を見たかが伝わるようにする）

## 未確認の項目
（pip-audit を実行できなかった、など）
```

重大度の目安:
- **高**: 現実的な条件で、APIキーの漏えい・第三者による課金・ユーザーデータの流出が起きる
- **中**: 公開のしかたや入力内容などの条件がそろえば起きる。または、被害が限定的
- **低**: 多層防御・衛生面の改善（バージョン固定、上限の設定など）
- **情報**: 設計上の判断として受け入れてよいもの。ただし利用者が知っておくべきもの

レポートはチャットに出力する。ユーザーがファイルを求めたら `security-report.md` としてリポジトリのルートに保存する（APIキーなどの秘密情報は書かない）。
